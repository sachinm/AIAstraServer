## 1. What was built

### 1.1 Heavy tone (server commit 1)

- `src/reading/self/sub/pressure.ts`: `reasons` carried from the payload (`null` when the engine sent none).
- `src/reading/self/sub/rowTone.ts`: `gradeRow(row)` → `{ tone, engine, bad, good, softened }`. Dasha and annual
  `presses` with `>= PRESSES_MIN_BAD_FLAGS` of `PRESSES_BAD_FLAGS` → heavy, fewer → mixed; `mixed` → mixed;
  `supports` → light; transits, Saturn's passage, stations, returns and rows without a stored list keep the engine word.
- Used by `v3/yearFrame.ts` (merge, each clock's tone per span, the year rows, the rows list) and `slices/render.ts`
  (`rowLine` writes `tone=` beside the engine's `polarity=` and `flags=`; the clock reader validator checks `tone=`).
  The prompts tell the readers to follow `tone=`.
- Provenance: each clock per span keeps `polarity` and `flags`; each span keeps `spineTone`.
- `heldTone`: the span's tone is the one tone held by at least `READING_CLOCKS_MIN` clocks; two tones both that wide, or
  none, is not held (`tone: 'mixed'`, `held: false`; the rail shows no tone word).
- Tests: `tests/unit/reading/self/v3/heavyTone.test.ts` (rule, env, reasons mapping, slice line, one clock light against
  four heavy, the spine alone, one flag everywhere, the YEARS line).

### 1.2 Wiring (server commit 2)

- Sync: `defaultEnsurePressure` (`src/services/kundliSyncWorker.ts`) calls `writeSlicesAtSync`
  (`src/reading/slices/prepare.ts`): stored inventories → a frame (spine edges, the stored year row) → `renderSliceSet`
  → `writeSlices` (changed hashes only). No `natal.core` at sync (it needs the digest packs).
- Sweep: `findKundlisMissingClocks` (digest ready, fewer settled inventories than `READING_CLOCKS - 1`) and
  `runClockSetPull` under the kundli's lease, after the incomplete-kundli pass, while 30 s of budget remain.
- Caller-side failures: `isEngineAnswer` stores a `failed` row only for the engine's own refusal; credentials, network
  and timeouts store nothing.
- Build: with `READING_CLOCK_LAYER=1`, `natal.core` (from the v2 natal prefix) plus the rendered set go through
  `prepareSlices`, then `runClockLayer`; its spend counts toward the Oracle's cap; the ledger and a summary are on the
  step result. Tests: `tests/unit/reading/self/v3/clockWiring.test.ts`, `clockSet.test.ts`, `v2/pressure.test.ts`.

### 1.3 A reading per card (server commit 3)

- Registry (`v3/cards.ts`): each card's engine matter keys; the ten Phase C cards (`briefOnly`) are offered while the
  per-card reading is on (`isCardOffered`); `READABLE_CARDS` = 21.
- Prompts: `cards/oracle.md` (the role) and `cards/self/<id>.md` × 21 (what the card answers, what it reads, what it
  leaves to other cards). Embedded with `node scripts/embed-prompts.mjs` (84 prompt files).
- `src/reading/cards/`:
  - `oracle.ts` `readCardOracle`: system = the common reader prompt, `parts[0]` = the clock layer's shared prefix (the
    region it warmed), `parts[1]` = role, brief, the board's titles, the frame with held tones, the card's ledger cells,
    its `matter.*` slices, the person's answers. Validated by `checkOracleCard` plus `checkAgainstLedger`; one repair alone.
  - `run.ts` `readCards`: asked-for cards, then the board (8 at once), then the rest (2 at once, `CARDS_READ_REST=1`),
    then cards queued meanwhile; per card `reading` → Oracle → Personalizer (`self.card.personalizer`, one repair) →
    `technique_outputs` (`self.card.reading`) → `done`; a failure is that card's alone; the spend cap is checked before
    every card. Spans gain `agreement` and `clocks` (plain labels) from the frame.
  - `state.ts`: one `area_builds` row per kundli per day (`self.cards`): per-card state, the day's spend, the stage,
    the clocks, cap reached, preparing. A `queued`/`reading` entry older than 10 min reads failed.
  - `store.ts`: newest stored reading per card on the board's clock.
- Build (`v3/build.ts`): with the per-card reading on, nothing runs (no clock reader, no card) until the board holds
  `CARDS_READ_MIN` cards or a card was asked for; then the clock layer, then `readCards`; the three-call Oracle is
  skipped. No ledger → stage idle, `preparing` when fewer than three clocks are stored.
- API (`v3/service.ts`, `routes/selfV3Routes.ts`): `PUT /api/self/v3/layout` with 5+ cards marks the unread board cards
  `queued`, queues the build, and returns `reading: { queued }`; `POST /api/self/v3/cards/:id/read` → 202 / 400 / 404 /
  409 / 429 / 503; `GET /api/self/v3` adds `state` per card and `reading` (stage, clocks, done of total, cap, preparing).
- Registered: agents `self.card.oracle`, `self.card.personalizer`; technique `self.card.reading` (catalogue,
  illustrations page 54, pieces doc regenerated).
- Tests: `tests/unit/reading/cards/cards.test.ts`, `tests/unit/reading/self/v3/routesCards.test.ts`, the build-branch
  cases in `clockWiring.test.ts`.

### 1.4 Web (web commit `865e4a2`, `AIAstra_WEB` worktree `wt/web-self-v3`)

`src/lib/selfV3Api.ts` mirrors the new types and adds `readSelfV3Card`; `src/pages/you/v3/` shows per-card states

## 2. Flags and defaults

| Env | Default | What it does |
|---|---|---|
| `SELF_V3_BUILD` | off | the v3 step |
| `READING_CLOCK_LAYER` | off | slices + clock readers + ledger in the v3 step |
| per-card reading | off | on only when both flags above are `1` (`isCardsReadEnabled`); offers the Phase C cards |
| `CARDS_READ_REST` | off | read every other offered card after the board |
| `CARDS_SPEND_CAP_USD` | 0.75 | per person per day, card readings and the clock layer |
| `CARDS_READ_MIN` | 5 | board size that starts the reading (saving still needs 3) |
| `CARDS_BOARD_PARALLEL` / `CARDS_REST_PARALLEL` | 8 / 2 | cards read at once |
| `PRESSES_MIN_BAD_FLAGS` | 3 | heavy needs this many stored bad flags (1 = the engine's own tone) |
| `PRESSES_BAD_FLAGS` / `PRESSES_GOOD_FLAGS` | the six / `functional_benefic,yogakaraka` | the flag lists |
