# 10 — Subject prompt matrix and data requirements

Added 2026-10-24. One row per life question the engine must answer. The **Data needed** columns are the build list for the Python engine (AIAstra_Radha): anything marked *need* is not exported today and must be added to the `facts` / `transits` export types (file 03) or as a new type. The **Rules** column says which tradition's rules the specialist applies and must name in its findings.

Legend for status: **have** = exported today (d1, d2, d4, d7, d9, d10, charakaraka, vimsottari, narayana, biodata); **facts** = planned in the Phase 1 dossier (file 03); **need** = new computation not derivable from the stored JSON.

**Who builds what.** Sachin asked that the Python engine stay untouched during Phase 1, so the dev session derives everything marked **facts** in Node from the stored kundli JSON plus a TypeScript ephemeris (house lords, aspects, arudhas, nakshatra lords, dasha boundaries, transits). Everything marked **need** requires pyjhora computations that are not in the stored JSON (extra vargas, shadbala, ashtakavarga, yogas, Chara/Sudasa dashas, Tithi Pravesha, Ashtakoota). That list is Sachin's own later "scalpel" pass on Radha; §2 below is written as that build list, with the pyjhora functions named. Until those exports exist, the specialists receive a caveat for the missing layer and the verdict cap in file 11 §5 applies.

## 3. Prompt rows (what each specialist is told per subject)

Each subject gets a short **prompt row** in `src/reading/prompts/subjects/<id>.md` with four fixed headings so the specialists stay consistent:

```
# <subject>
## Establish      – the 2–4 questions the reading must answer
## Read in order  – houses → lords → karakas → varga → arudha/special → yogas/strength → dasha → transit → nakshatra
## Deciders       – the one or two factors that settle a split verdict (see file 11 §3)
## Say / never say – policy lines, caveats, banned phrasing
```

Example, `marriage_timing.md`:

```
# Marriage timing
## Establish
Is marriage promised (7th, 7th lord, Venus/Jupiter, DK, UL in D-1 and D-9)? Which periods can deliver it in the horizon? Which transit fires it?
## Read in order
7th house, 7th lord (placement, dignity, aspects), Venus (and Jupiter for a female chart), DK, UL and 2nd/7th from UL; D-9 lagna, D-9 7th, D-1 7th lord in D-9; doshas with cancellations; Vimshottari periods of 7th lord/Venus/DK/UL lord; Narayana and Chara dasha of 7th/UL sign; Jupiter and Saturn double transit on 7/7th lord/UL/Venus.
## Deciders
Split verdict → D-9 7th lord dignity and the double transit decide. Promise weak in D-1 but strong in D-9 → late or unconventional marriage, not denial.
## Say / never say
Give windows, not a wedding date. Never say "no marriage"; say "not indicated in this horizon".
```

## 4. Tradition tags the specialists must emit

Every claim carries `tradition: 'parashara' | 'jaimini' | 'nakshatra' | 'tajaka' | 'kuta' | 'kp_starlord'`. The synthesizer may mention it in "How I read this" ("by Jaimini's Upapada rule"). This keeps mixed-school reasoning honest and lets evals check that, for example, an Upapada claim is tagged Jaimini and a 7th-lord claim Parashara.
